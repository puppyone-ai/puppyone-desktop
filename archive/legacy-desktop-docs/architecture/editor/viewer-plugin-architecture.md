# Viewer Plugin Architecture

内置 Viewer 使用“格式家族拥有 Contribution、中央 Registry 组合”的结构。一个格式家族可以共享一个 Contribution 文件，例如音频与视频；语义和依赖不同的格式应各自拆分。Contribution 只声明匹配、输入、能力和懒加载入口，不拥有资源身份、Working Copy、保存队列或冲突处理。

Viewer Pack 第一版只扩展只读展示，不进入编辑和持久化信任边界。主进程验证清单、签名、格式声明和资源；渲染进程只接收已验证的 Contribution。

插件不能获得可编辑文档源、文档持久化端口、任意本地路径或进程能力。资源使用共享的可撤销 URL 租约；失败时回退到内置占位或系统外部打开。

未来若开放可编辑插件，必须先提供受版本化协议约束的模型适配器、事务来源、资源配额和冲突测试，不能直接暴露文件写入能力。
